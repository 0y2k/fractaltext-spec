## 1. 概要

FractalTextは以下をアイテムとして持つことのできる，再帰的な平文データ構造である．
```haskell
type Key = Text
data Item
  = Item'List [Text]
  | Item'Dict [(Key, Item)]
```

## 2. 構文規約

### 2.1. Lines
- **行**は改行によって区切られる部分である．
  * 各行は行頭にインデントを含むことができる．
  * 行は空行(blank line)，コメント行(comment line)，キー行(key line)，値行(string line)の4つに分類される．
- **改行**は論理的な行を終了させる．
  * 改行文字として，LF(`'\n'; 0x0A`), CRLF(`'\r\n'; 0x0D 0x0A`), CR(`'\r'; 0x0D`)がこの順序で解釈され使用できる．
- **インデント** (行頭のホワイトスペース)は各アイテムの再帰的な構造を表現するのに使用される．
  * インデントの文字として，スペース文字(`' '; 0x20`)のみが許可される．
  * タブ文字(`'\t'; 0x09`)はインデントやホワイトスペースとしては解釈されない．
    インデントとしてタブ文字が存在すると，即時にエラーを起こす(SHOULD)．

### 2.2. Line kinds

#### 2.2.1. Blank lines
- **空行**(blank line)はインデントのみで構成される行，もしくは連続する2つの改行で挟まれる行である．

#### 2.2.2. Comment lines
- **コメント行**(comment line)はハッシュ文字(`'#'; 0x23`)で始まり，行末の改行の手前までからなる．
  * 行末のコメントは解釈されない．行頭のコメントのみが無視される．

#### 2.2.3. Key lines
- **キー行**(key line)はコロン文字(`':'; 0x3A`)で始まり，行末の改行の手前までからなる．
- **キー**はキー行の行頭のインデントとコロンを除いた部分である．

#### 2.2.4. Value lines
- **値行**(value line)は上記の3つに分類されない行である．
- **値**は値行の行頭のインデントを除いた部分である．
  * 値がダブルクオート(`'\"'; 0x22`)で囲まれている場合は，それを取り除いたものを値とする．
    このルールは一度だけ適用される．

## 3. 意味規約

### 3.1. Parsing rules
- 解釈は行ごとに実行される．
- 空行とコメント行は無視される．

### 3.2. Item rules
- アイテムは値のリスト，もしくはエントリのリストである．
  * 値のリストは`Item'List`として，エントリのリストは`Item'Dict`として解釈される．
  * 値とエントリを混在させることはできない．
- **エントリ**とは，キー行と直後のより深いインデントをもつ子アイテムのペアである．
  * `Item'Dict`の各要素に対応する．
  * 直接の子の関係にあるアイテムは全て同じインデントをもち，キー行のインデントとの間に別の子が混在してはならない．
  * そのような行が存在しない場合，空のリストが直接の子となる．

### 3.3. Document rules
- ドキュメントは入力全体が表現する1つのアイテムを指す．
  * 入力は全体として1つのアイテムにする必要がある．
  * `Item'List`と`Item'Dict`の混在は許可されない．
